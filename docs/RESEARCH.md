# 研究结果与边界

本文整理本地研究中已取得的结果，不包含原始游戏纹理、进程日志或反汇编文件。原始材料未随仓库发布，因此这些历史运行结论不是克隆仓库后即可自动复现的测试结果。

## 目标渲染链

```text
游戏输出尺寸
    ↓ 查询 DLSS 档位的 optimal / min / max
引擎按较低内部尺寸渲染颜色、深度与运动矢量
    ↓ 携带对应帧的投影抖动与历史状态
一次现代 DLSS SR 重建
    ↓ 完整输出尺寸，正确衔接后处理取样
游戏最终画面与 UI
```

输出尺寸来自游戏运行时的渲染目标，而不是桌面分辨率。把完整渲染的画面事后缩小再交给 DLSS，不能实现这里要求的引擎渲染开销降低。

## 输入数据

MHWSS 已有现代 NGX 调用路径，研究时曾临时使用其 DLAA 入口获得参数和纹理。这个采集手段不代表最终方案需要叠加 DLAA。

| 数据 | 观察到的格式或值 |
|---|---|
| Color / Output | `DXGI_FORMAT_R11G11B10_FLOAT`，格式编号 26 |
| Depth | `DXGI_FORMAT_R32_FLOAT`，编号 41 |
| 已解码 MV | `DXGI_FORMAT_R16G16_FLOAT`，编号 34 |
| 原始编码 MV | `DXGI_FORMAT_R32_UINT`，编号 42 |
| NGX flags | `0x4B`：HDR、低分辨率 MV、反向深度、自动曝光 |
| 原 MHWSS MV.Scale | `(-0.5, +0.5)` |
| 抖动 | 非零；与入口数据的 `(-0.5, +0.5)` 换算得到成对样本支持 |

在 2560×1440 输出下，Low 档的几何视口、scissor 和纹理像素都支持有效区域为左上角 1920×1080。纹理分配仍是 2560×1440，因此仅检查 `GetDesc()` 会漏掉实际内部降分辨率。

已分析的运动矢量解码包含半精度解包、当前/上一帧投影抖动差，以及分配尺寸缩放。相关说明代码为 [MhwPackedMotionDecode.hlsl](../shaders/MhwPackedMotionDecode.hlsl)。转换到 SR 输入像素单位的候选方式是再乘以“有效输入尺寸 / 分配尺寸”；连续帧的方向、单位、遮挡解除和历史对齐仍需验证。

## 独立现代 SR 回放

[MhwSrReplay](../replay/MhwSrReplay.cpp) 在独立 D3D12 设备上使用真实 Low 输入区域，得到以下结果：

- DLSS DLL 版本：`310.9.1.0`。
- 输入：1920×1080；输出：2560×1440。
- `PerfQualityValue=2`，preset K，`Reset=1`。
- 特征创建、evaluate 与 GPU fence 后回读成功。

这是 **一张实际输入的独立回放**。它没有插入游戏渲染链，没有连续帧历史验证，也没有游戏性能结果。

该运行库针对 2560×1440 输出返回的设置：

| 档位 | 枚举 | Optimal | Minimum | Maximum |
|---|---:|---|---|---|
| 质量 | 2 | 1707×960 | 1280×720 | 2560×1440 |
| 平衡 | 1 | 1485×835 | 1280×720 | 2560×1440 |
| 性能 | 0 | 1280×720 | 1280×720 | 2560×1440 |
| 超高性能 | 3 | 853×480 | 853×480 | 853×480 |

这些是指定输出、运行库和采集环境下的查询结果，不应替代运行时查询。

## 引擎内部比例与后处理

使用游戏原有 setter，在帧更新边界请求约 2/3 内部比例；引擎按 16 像素宽度对齐，实际比例为 `0.662500024`，观察到 1696×954 主视口和 848×477 半尺寸视口。约 3 秒后恢复比例 1。游戏输出字段与设置保持 2560×1440，操作者确认画面完整、无报错。

随后在 MHWSS Upscaler=None 的情况下记录到后 TAA 拷贝：

| 参数 | 实测 |
|---|---|
| 源矩形 | `[0, 0, 1696, 954]` |
| 源纹理分配 | `[2560, 1440]` |
| 目标上下文视口 | `[0, 0, 2560, 1440]` |
| UV 偏移 | `[-0.5/2560, -0.5/1440]` |
| 绘制 | 全屏三角形；上下文与主场景匹配 |

窗口内记录 4580 次 quad 调用，其中指定后 TAA 调用位置 316 次，去重后 1 条矩形记录。比例和钩子均恢复。

这定位了低分辨率区域向完整视口取样放大的步骤。将完整 SR 输出写回同一纹理后，必须协调该步骤，避免仍然只取左上角。矩形改写与半像素偏移的处理尚未启用或验证。

## 场景调用与抖动

原生 TAA 的命令记录没有落在此前记录的场景函数线程局部范围内，不能用该 CPU 作用域传递后来提交的 GPU 帧尺寸。独立追踪真实 D3D12 compute CBV 绑定后，一个窗口取得 594 份有效的 TAA 当帧 CBScreen：350 份输入为 1696×954，244 份为 2560×1440，输出均为 2560×1440；无无效记录。

通过 PE 链式 unwind 信息定位的完整场景函数入口为游戏 RVA `0x23c3790`。其初段按该场景的 actual scale 乘以上下文矩形的四个坐标，以截断方式转为整数，再将结果保存在本次调用的栈上。桥接前置观察器据此记录同一次调用的范围，避免只按时间戳或后来读取的全局比例推断帧关联。

旧 NGX 参数记录中，High 的 200 个非零样本、Low 的 112 个样本均匹配居中的 Halton(2,3) 前 8 个位置。稀疏采样不能证明精确周期。若投影抖动仍按输出尺寸归一化，内部比例下降会缩小输入像素中的抖动覆盖；仅改变传给 NGX 的 jitter 数值不会改变已经光栅化的采样位置。

上述 594 份新记录的投影抖动实际全为零，尽管字段读取及有限值检查都通过。完整投影矩阵采样与 MHWSS 的开关分析进一步解释了原因：`Upscaler=None` 同时关闭 MHWSS 的独立投影抖动开关。不能把旧 DLAA 入口的非零抖动结论直接套用到 None 模式。

短暂启用独立投影抖动后，在保持 MHWSS=None 的联合采集中取得 530 份有效尺寸记录。其中 324 个低内部尺寸帧具有非零当前抖动，529 对相邻记录的历史抖动连续；八个不同样本在输入像素单位中的覆盖范围，符合输出归一化模式再乘以 0.6625。没有启用 MHWSS 的 TAA 旁路/上采样执行，窗口结束恢复原开关。这仍是相机参数验证，不是连续帧 DLSS 画质验证。

## 实际放大三角形

同一联合采集通过引擎顶点绑定函数找到三个真实 4 MiB 上传缓冲区。324 次低内部尺寸绘制均读到完整全屏三角形，其 UV 为 `(0,0)`、`(0,1.32430565)`、`(1.3246094,0)`，与先前 CPU 侧源矩形和半像素偏移一致；目标视口为 2560×1440，没有读失败。代码只观察，未修改绘制。资源引用、映射、钩子、比例和抖动开关均恢复。操作者确认该窗口画面完整，无明显闪烁或报错。

这确认了原有空间放大的实际 GPU 顶点输入。后续已完成实际颜色纹理对应，并定位两次中间处理，详见 [真实纹理链](TEXTURE-GRAPH.md)。

最新记录将 TAA 输出经局部复制、动态模糊重建、色调映射到最终放大的源目标串联起来。低比例时，前两次后处理仍使用低视口和 scissor，色调映射 UV 上限也随比例缩小。完整 SR 输出不能只靠修改最后一次放大来接回。

同时发现原生 TAA 的深度槽绑定 1×1 占位纹理；MHWSS 另有独立全尺寸 R32 深度准备路径。高档只读窗口中，269 次 TAA 与当前命令列表 Reset 代次内的准备调用对应，首个中途接入记录被排除。此结果尚非 GPU 同步或像素内容验证。

用户已将动态模糊设为 Off，并明确要求首版默认关闭。该绘制仍存在，实测普通快门为 0、毛发快门参数为 0.4，因此后续 SR 路径需要明确处理它，不能默认它已成为无条件复制。

## 无外部宿主的原生输入

2026-10-06，独立启动器加载自有原生输入模块，进程未加载 MHWSS，D3D12 使用系统 DLL。通过原生资源创建与计算管线创建接口识别出 48 MiB 上传缓冲和原生 TAA PSO。10 秒窗口共观察 39985 次 dispatch，其中 1084 次 TAA 的相机／屏幕绑定均已刷新，全部通过范围、代次和有限值检查。

输入与输出均为 2560×1440，TAA dispatch 为 `[160,90,1]`，实际比例为 1，当前和历史投影抖动均为零。采集结束后原生 API 钩子恢复。该结果确认常量缓冲并不是外部工具私有、不可独立取得的数据，但未执行独立 SR。

下一版在原生投影 getter 返回后、游戏复制矩阵前接入自有抖动。先以未修改的 TAA 投影匹配唯一主视图，确认栈上临时矩阵与实际尺寸，再进行有时间上限的写入。v2 已编译，尚无本轮运行证据；不能用旧桥接阶段的非零抖动替代它的验证。控制流程和限制见 [独立入口说明](STANDALONE.md)。

## 尚不能得出的结论

尚不能宣称游戏内现代 SR 可用、时域画面正确、帧率提升、四档切换可用或 UI 已完成。引擎现有比例下限为 0.5，质量／平衡／性能有候选控制路径；超高性能约 1/3 需要额外适配。
